# 이미지 아카이브 사이트 설계

## 1. 목적과 콘셉트

개인 창작물, 박물관 작품을 바탕으로 한 커스텀, 직접 고른 퍼블릭 도메인 이미지를 한곳에 모으는 이미지 아카이브다.

- 설명문 없이 작품 정보(제목, 제작일, 재료 등)만 보여 준다.
- 이미지가 화면의 중심이고, 메뉴와 정보는 작고 절제된 형태로 둔다.
- 굿즈 구매 연결은 제공하지만 사이트의 중심 기능으로 두지 않는다.

## 2. 콘텐츠 모델

### 2.1 게시물 종류

| 종류 | 의미 | 그리드 표시 |
|---|---|---|
| `work` | 직접 만든 창작물 | 표시 없음 |
| `custom` | 박물관 작품을 재채색하거나 요소를 강조해 만든 작품 | 표시 없음 |
| `collected` | 수집한 퍼블릭 도메인 이미지 | 표시 없음 |

세 종류는 한 피드에 섞어서 게시일 최신순으로 보여 준다. 피드에서는 종류를 표시로 구분하지 않고, 상세의 작가 이름과 원작·커스텀 묶음으로 구분한다.

### 2.2 디자인과 형태

work·custom은 **디자인** 단위로 관리하고, 하나의 디자인은 여러 **형태**의 게시물로 나뉜다.

- 디자인 하나에는 항상 `이미지` 형태(그림 자체) 게시물이 하나 있다.
- 굿즈로 판매하는 형태(머그, 포스터, 액자, 티셔츠 등)마다 게시물이 하나씩 더 생긴다.
- 예: `붓꽃 들판`을 머그와 포스터로 판매하면 피드에 `붓꽃 들판`(이미지), `붓꽃 들판 머그`, `붓꽃 들판 포스터` 세 게시물이 나온다.
- 굿즈 형태 게시물의 제목은 `디자인 제목 + 형태 이름`이고, 제작일·원작은 디자인에서 물려받는다.
- collected는 디자인으로 묶지 않는다.

### 2.3 게시물 항목

| 항목 | 화면 이름 | work | custom | collected | 형식 |
|---|---|:-:|:-:|:-:|---|
| 제목 | 제목으로 표시 | 필수 | 필수 | 필수 | 문자열. 한국어로 쓰고, 한국어 제목이 없는 고유 명칭만 원어로 쓴다. |
| 제작일 | 제작일 | 필수 | 필수 | 필수 | 문자열(예: `2026.10`). collected는 원작의 제작 연도(예: `1890년경`) |
| 재료 | 재료 | 필수 | 필수 | 필수 | 문자열(예: `디지털, 재채색`, `캔버스에 유채`) |
| 원작자 | 작가 | – | – | 필수 | 문자열(한국어 표기) |
| 출처 | 출처(툴팁) | – | – | 필수 | 기관 이름(한국어 표기) + 원본 페이지 URL. URL은 기록용이며 화면에 링크로 쓰지 않는다. |
| 라이선스 | 라이선스(툴팁) | – | – | 필수 | `CC0`, `퍼블릭 도메인`, `공공누리 1유형` 중 하나 |
| 원작 | 원작 | – | 필수(1개 이상) | – | collected 게시물 식별자 목록. 디자인에 한 번 적으면 모든 형태에 적용 |
| 디자인 | – | 필수 | 필수 | – | 같은 디자인끼리 묶는 식별자 |
| 형태 | 형태 선택 칩 이름 | 필수 | 필수 | – | `이미지`, `머그`, `포스터`, `액자`, `티셔츠` 등 |
| 판매처 | 구매하기 | 필수 | 필수 | – | 굿즈 형태는 그 상품의 판매처 URL, 이미지 형태는 디자인 전체 상품 페이지 URL |
| 태그 | – | 선택 | 선택 | 선택 | 문자열 목록. 화면에는 표시하지 않는다. |
| 게시일 | – | 필수 | 필수 | 필수 | 날짜. 피드 정렬에만 쓴다. |
| 대표 이미지 | – | 필수 | 필수 | 필수 | 피드와 상세의 첫 이미지. 굿즈 형태는 정면 사진 |
| 추가 사진 | – | 선택 | 선택 | – | 굿즈 형태의 다른 각도 사진(예: 머그 측면·뒷면). 대표 이미지 포함 3장 안팎 |

### 2.4 자동으로 만드는 정보

- **커스텀:** custom의 원작 목록을 역으로 모아, 각 collected 게시물에 그 원작을 사용한 커스텀 디자인(이미지 형태 게시물) 목록을 만든다.
- **형태 선택:** 같은 디자인의 모든 형태 게시물을 모아 만든다.
- **판매품 필터 항목:** 굿즈 형태 게시물의 형태 이름을 모아 만든다. 표시 순서는 액자, 머그, 포스터, 티셔츠를 기본으로 하고, 새 종류는 뒤에 붙인다.

### 2.5 라이선스 규칙

- collected 게시물과 custom의 원작은 상업적 이용과 변경이 모두 허용된 이미지만 쓴다.
- 허용 라이선스는 CC0, 퍼블릭 도메인 표시, 공공누리 1유형이다. 공공누리 2·3·4유형은 쓰지 않는다.
- 출처 표시는 각 상세 페이지의 작가 항목과 이미지 우상단 `?` 툴팁(출처, 라이선스)으로 충족한다.

## 3. 페이지 구성

화면에 보이는 문구는 한국어로 쓴다. 사이트 이름, 인스타그램 계정, 라이선스 표기(`CC0`)처럼 원래 표기가 정해진 것만 그대로 둔다.

```
상단 바 (모든 페이지 공통)
├─ 사이트 이름 → Home
├─ @instagram → 인스타그램(새 탭)
└─ 정보 → 정보 페이지

Home  /
├─ 사이트 이름(대형)
├─ 판매품 필터
└─ 이미지 그리드 → 상세

상세  /p/{게시물 식별자}
├─ 이미지
├─ 이 게시물 정보(제목, 작가·재료, 제작일)
├─ 구매하기 → 외부 판매처(work·custom)
├─ 형태 선택 칩(같은 디자인)
├─ 원작(custom) 또는 커스텀(collected) 카드
└─ 이전 / 다음 게시물

정보  /info
└─ 원형 프로필 이미지, 이름, 소개, 이메일(텍스트), 인스타그램·판매처 버튼(항목 이름 없음)
```

### 3.1 상단 바

- 화면 위에 고정한다. 높이는 PC 64px, 휴대폰(760px 이하) 52px이다. PC 상세 패널의 고정 위치와 홈 상단 바 이름이 나타나는 시점은 이 높이를 기준으로 한다.
- 왼쪽은 사이트 이름, 오른쪽은 `@instagram`과 `정보`다. 상세 페이지에서는 오른쪽 끝에 `닫기 ×`가 더해진다.
- 현재 보고 있는 페이지의 메뉴(정보)는 강조색으로 표시한다.
- Home에서는 대형 사이트 이름이 화면에 보이는 동안 상단 바의 사이트 이름을 숨기고, 스크롤로 대형 이름이 지나가면 나타낸다. 다른 페이지에서는 항상 보인다.

### 3.2 Home

- **머리 부분:** 사이트 이름 한 줄을 화면 폭에 맞춰 크게 표시한다. 문구나 설명은 넣지 않는다.
- **판매품 필터:** `전체`와 굿즈 종류(액자, 머그, 포스터, 티셔츠 등)를 작은 글자 한 줄로 둔다. 기본은 `전체`다. 굿즈를 고르면 그 형태의 굿즈 게시물만 남는다.
- **그리드:** 높이가 다른 이미지를 여러 열에 쌓는 벽돌형 배치다. 최신순이 왼쪽에서 오른쪽으로 읽히도록 각 이미지를 가장 짧은 열에 차례로 넣는다. 열 수는 PC 4열, 태블릿 3열, 휴대폰 2열이다.
- **타일:** 이미지만 보인다. PC에서 마우스를 올리면 왼쪽 아래에 `제목, 연도`가 나타난다. 휴대폰에서는 글자를 표시하지 않는다.
- **상세 패널(화면 폭 1024px 이상):** 이미지 검색 결과 화면처럼, 타일을 누르면 페이지를 이동하지 않고 화면을 둘로 나눈다.
  - 왼쪽은 그리드, 오른쪽은 선택한 게시물의 상세 패널(폭 46%, 최대 820px)이다. 그리드는 남은 폭에 맞춰 열 수가 줄고, 계속 스크롤해서 다른 이미지를 볼 수 있다.
  - 패널은 상단 바 아래에 고정되고, 내용이 길면 패널 안에서 따로 스크롤한다.
  - 다른 타일, 패널 안의 형태 선택 칩, 원작·커스텀 카드를 누르면 패널 내용만 바뀐다. 선택된 타일은 강조색 외곽선으로 표시한다.
  - 패널의 이미지 영역을 누르면 그 게시물의 상세 페이지로 이동한다. `?` 버튼과 썸네일을 누른 경우, 사진을 끌어 넘긴 경우는 이동하지 않는다.
  - `닫기 ×` 버튼은 패널 오른쪽 위에 두고, 패널 내용을 스크롤해도 맨 위에 고정되어 항상 보인다.
  - `닫기 ×` 버튼이나 Esc 키로 닫으면 그리드가 원래 열 수로 돌아온다.
  - 주소에 선택한 게시물(`?p=식별자`)을 남겨, 그 주소로 들어오면 패널이 열린 상태로 시작한다.
  - 패널 내용은 상세 페이지와 같고, 이전/다음 버튼은 두지 않는다.
- **화면 폭 1024px 미만:** 타일을 누르면 상세 페이지로 이동한다.

### 3.3 상세

상세 페이지는 휴대폰·태블릿에서 타일을 눌렀을 때, PC 패널의 이미지를 눌렀을 때, 상세 주소로 바로 들어왔을 때 쓴다. 내용 구성은 PC 홈의 상세 패널과 같다.

- **닫기 ×:** 상세 페이지에서만 상단 바 오른쪽 끝(`정보` 오른쪽)에 작은 알약형 버튼으로 둔다. 상단 바와 같은 줄·같은 여백이라 이미지 크기와 관계없이 항상 화면 오른쪽 위 같은 자리에 있고, 상단 바와 함께 고정되어 스크롤해도 보인다. 사이트 안에서 넘어왔으면 이전 화면(예: 패널이 열린 홈)으로 돌아가고, 링크로 바로 들어왔으면 홈으로 간다. Esc 키도 같다. 패널 이미지를 눌러 페이지가 바뀐 것을 알아채지 못한 사람도 이 버튼으로 원래 화면에 돌아갈 수 있게 하기 위한 것이다.

- 화면 크기와 관계없이 이미지, 이 게시물 정보, 관련 게시물 순으로 위에서 아래로 쌓는다. 정보를 이미지 옆에 두지 않는다.
- 이미지는 가운데 정렬하고, 높이는 화면 높이에서 상단 바와 여백을 뺀 값을 넘지 않는다. 휴대폰에서는 화면 폭에 맞춘다.
- 이미지 아래 정보는 왼쪽 여백에 맞춰 최대 폭 640px 안에 두고, **이 게시물 정보**와 **관련 게시물(원작·커스텀)** 두 묶음으로 나눈다. 항목 이름(라벨)은 쓰지 않고, 글자 크기·색과 요소 모양으로 위계를 만든다.
- **이 게시물 정보**(위에서 아래로):
  1. 제목: 가장 큰 글자
  2. 작가(collected만): 14px 검정
  3. 재료: 14px 검정
  4. 제작일: 13px 보조 글자색
  5. 형태 선택(같은 디자인에 형태가 둘 이상일 때): 같은 디자인의 모든 형태를 작은 알약형 칩으로 나열하고, 지금 형태는 강조색 테두리·글자로 선택 상태를 표시한다. 다른 칩을 누르면 그 형태 게시물로 이동한다. 예: `이미지` `머그` `[포스터]`
  6. 구매하기(work·custom의 모든 형태): 검정 바탕에 흰 글자인 채워진 버튼. 페이지에서 유일한 주요 행동 버튼이다. 굿즈 형태는 그 상품의 판매처 URL, 이미지 형태는 디자인 전체 상품 페이지 URL로 연결한다.
- **관련 게시물**: 구분선 아래에 작은 회색 제목(`원작` 또는 `커스텀`)과 카드 줄을 둔다. 원작은 같은 디자인 묶음이 아닌 별도 게시물이므로 형태 선택과 섞지 않는다. 디자인의 모든 형태 게시물에 같은 원작이 표시된다.
- **추가 사진(있을 때만):** 대표 이미지 뒤에 추가 사진을 이어 붙인 갤러리로 보여 준다. 한 번에 한 장이 보이고, 아래에 52px 정사각형 썸네일 줄을 둔다. PC는 마우스로 좌우로 끌거나(50px 넘게 끌면 이웃 사진으로 넘어감), 썸네일을 누르거나, 방향키(←, →)로 넘긴다. 휴대폰은 옆으로 밀어서 넘긴다. 지금 보이는 사진의 썸네일은 강조색 외곽선으로 표시한다. 피드에는 대표 이미지만 쓴다.
- **출처·라이선스(collected만):** 이 게시물 정보에 넣지 않고, 이미지 영역(이미지 자체가 아니라 이미지를 담는 전체 폭 영역)의 우상단에 원형 `?` 버튼(지름 24px)으로 고정한다. 이미지 크기·비율과 관계없이 같은 위치에 보인다. PC에서는 마우스를 올리면, 휴대폰에서는 누르면 버튼 아래에 툴팁이 열린다. 툴팁은 검정 바탕에 `출처 기관 이름`, `라이선스 CC0` 두 줄을 보여 주며, 링크는 걸지 않는다.
- **원작·커스텀:** 카드로 표시한다. 카드는 정사각형 썸네일과 그 아래 두 줄 캡션(첫 줄 제목, 둘째 줄 원작은 작가·커스텀은 제작일)으로 이루어지고, 카드 전체가 해당 게시물로 가는 링크다. 마우스를 올리면 썸네일이 살짝 옅어지고 제목이 강조색으로 바뀐다. 원작·커스텀이 없으면 관련 게시물 묶음을 표시하지 않는다.
- **이전 / 다음:** 관련 게시물 아래 구분선 밑에 `← 이전`(왼쪽), `다음 →`(오른쪽) 알약형 버튼으로 둔다. 판매품 필터와 관계없이 전체 피드의 게시일 순서로 이웃 게시물로 이동하며, 첫 게시물에는 이전, 마지막 게시물에는 다음 버튼이 없다.

### 3.4 정보

항목 이름 없이 값만 위에서 아래로 쌓는다. 각 값은 형태만으로 무엇인지 알 수 있게 쓴다.

| 순서 | 내용 | 표시 |
|---|---|---|
| 1 | 프로필 이미지 | 원형, PC 지름 120px / 휴대폰 96px. 인물 사진이 아닌 대표 이미지 |
| 2 | 이름 | 게시물 제목과 같은 글꼴과 크기 |
| 3 | 소개 | 한 줄 문장 |
| 4 | 이메일 | 주소 텍스트만 보조 글자색으로 표시. 링크를 걸지 않는다. |
| 5 | 인스타그램 | `인스타그램 →` 버튼 |
| 6 | 판매처 | `스마트스토어에서 구매 →`처럼 판매처 이름과 행동을 함께 쓴 버튼 |

5~6의 버튼은 한 줄에 나란히 두고, 폭이 모자라면 다음 줄로 넘긴다. 모양은 검정 1px 테두리의 둥근 알약형이고, 마우스를 올리면 강조색 바탕에 흰 글자로 바뀐다.

## 4. 화면 디자인 규칙

### 4.1 색

| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| 배경 | `#F4F4F1`(미색) | 페이지 배경 |
| 글자 | `#000000` | 기본 글자 |
| 보조 글자 | `#84847F` | 항목 이름, 선택되지 않은 필터 |
| 구분선 | `#D9D9D4` | 이전/다음 위 구분선 |
| 강조 | `#002FA7`(클라인 블루) | 선택된 필터·타일·형태 칩, 현재 페이지 메뉴, 버튼·카드·텍스트 링크의 마우스 올림 상태 |

강조색은 위 네 곳 외에는 쓰지 않는다.

### 4.2 글꼴

영문 글꼴에 없는 한글은 같은 역할의 한글 글꼴로 표시한다.

| 역할 | 영문 | 한글 | 설정 |
|---|---|---|---|
| 대형 사이트 이름 | Archivo | – | 폭 62%, 굵기 900, 대문자 |
| 상단 바 사이트 이름 | Archivo | – | 폭 62%, 굵기 800, 18px |
| 게시물 제목 | Archivo | Pretendard | 폭 75%, 굵기 700, PC 34px / 휴대폰 28px |
| 작가·재료·제작일, 필터, 칩, 상단 바 링크 | IBM Plex Mono | 나눔고딕코딩 | 13px |

### 4.3 간격과 형태

- 좌우 여백(상단 바, Home, 정보): PC 20px, 휴대폰 12px
- 상세 페이지 본문(이미지, 정보, 구분선, 이전/다음)의 좌우 여백은 화면 폭의 12.5%다(1920px 240px, 1536px 192px, 1280px 160px). 휴대폰(760px 이하)은 20px로 고정한다. 1920px보다 넓은 화면에서는 본문을 1440px 열로 가운데 정렬한다. 구분선과 이전/다음 줄은 본문 열 전체 폭으로 이어진다.
- 그리드 간격: PC 6px, 휴대폰 4px
- 이미지 모서리: 3px
- 그림자, 그라디언트, 테두리 있는 카드는 쓰지 않는다.

### 4.4 접근성

- 글자는 12px 이상으로 한다.
- 키보드 초점은 강조색 외곽선으로 표시한다.
- 움직임 줄이기 설정을 켠 사용자에게는 전환 효과를 끈다.

## 5. 이미지 처리

- 원본 이미지는 게시물 폴더에 그대로 보관한다. 저장 방지나 워터마크는 넣지 않는다.
- 배포할 때 화면 표시용 이미지를 자동으로 만든다.
  - 그리드용: 긴 변 800px 안팎
  - 상세용: 긴 변 2000px 안팎
- 형식은 브라우저가 지원하면 WebP 또는 AVIF를 쓴다.

## 6. 게시물 추가 방식

- 사용자가 이미지와 정보를 전달하면 Claude Code가 게시물 폴더를 만들고 배포한다.
- 게시물 하나는 폴더 하나다.

```
src/content/posts/
└─ field-of-irises/
   ├─ index.md    # 2.2의 항목을 머리말(frontmatter)로 작성
   └─ image.jpg
```

- 폴더 이름이 게시물 식별자이자 상세 페이지 주소(`/p/field-of-irises`)가 된다. 영어 소문자와 `-`만 쓴다.
- 배포 전에 다음을 자동으로 검사하고, 어긋나면 배포를 멈춘다.
  - 필수 항목 누락
  - custom의 원작이 존재하지 않는 게시물을 가리키는 경우
  - collected의 라이선스가 허용 목록에 없는 경우

## 7. 기술 구조와 배포

- **사이트 생성:** Astro. 게시물 폴더를 읽어 Home, 상세, 정보 페이지를 정적 파일로 만든다.
- **동작 스크립트:** 판매품 필터, 그리드 배치, 상단 바 이름 표시, PC 홈의 상세 패널만 브라우저에서 동작한다. 상세 패널은 상세 페이지와 같은 렌더링 함수를 쓴다.
- **배포:** GitHub Pages(저장소 `leegnldong/archive`, `main` 브랜치)로 배포하며, 주소는 `https://leegnldong.github.io/archive/`다. 저장소에 변경을 올리면 자동으로 다시 배포된다.
- **브라우저 캐시:** GitHub Pages는 파일을 약 10분 동안 브라우저에 저장해 두게 한다. 수정 후 방문자가 예전 스타일을 보지 않도록, 페이지에서 CSS·JS를 부를 때 버전 표시(`style.css?v=날짜-번호`)를 붙이고 배포할 때마다 값을 올린다. 도메인을 구입하면 연결한다.
- **공유 미리보기:** 상세 페이지마다 제목과 이미지를 링크 미리보기 정보(Open Graph)로 넣는다.

## 8. 범위

### 8.1 포함하지 않는 것

- 관리자 화면, 로그인, 데이터베이스
- 결제와 주문 기능(외부 판매처 링크만 제공)
- 이미지 저장 방지
- 검색

### 8.2 나중에 추가할 수 있게만 준비하는 것

- 태그 기반 분류와 검색: 태그 항목을 미리 저장한다.
- 내 작품 / 수집 이미지 필터: 게시물 종류 항목으로 바로 만들 수 있다.
- 수집 이미지 출처 모음 페이지: collected 게시물 정보로 자동 생성할 수 있다.

## 9. 결정이 필요한 항목

| 항목 | 현재 상태 |
|---|---|
| 사이트 이름 | 시안에서 `ARCHIVE`를 자리표시로 사용 |
| 인스타그램 계정 | 시안에서 `@instagram_handle`을 자리표시로 사용 |
| 프로필 이미지·이름·소개·이메일·판매처 | 정보 페이지 시안에서 자리표시로 사용 |
